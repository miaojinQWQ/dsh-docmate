# 伴随式学习：从「查资料」到「有人陪」

> 这份笔记用来验收 Markdown 渲染器：标题、行内样式、列表、表格、代码块、引用、图片都要能读。

## 一、为什么需要「伴随」

传统检索是**打断式**的：你读到一半，切到搜索框，回来已经忘了上一句在讲什么。
伴随式阅读把 AI 放在**同一屏**的右侧，它的输入不是「你打的字」，而是「你正在看的那一段」。

| 方式 | 打断成本 | 上下文保真度 | 适合场景 |
| --- | --- | --- | --- |
| 另开聊天窗口 | 高 | 低（要复述） | 大问题、跨文档 |
| 划词翻译插件 | 低 | 中（只有词） | 术语、单词 |
| 伴随式阅读台 | 低 | 高（原段落 + 位置） | 精读、复习、写作 |

## 二、三条设计原则

1. **选区即输入**：划中哪一段，AI 就先看到哪一段，不用复述。
2. **原文可回溯**：每条回答都带着「来自《文件名》第 N 页」，能点回去。
3. **会话是连续的**：同一篇文档里的追问共享上下文，不要每次都从零开始。

### 2.1 一个具体的例子

假设你在读下面这句话：

> 「注意力的瓶颈不在算力，而在上下文窗口里能同时放下的有效信息量。」

划中它，点「解释」，右侧会收到：

```text
我在文档《深度学习入门笔记.md》里选中了下面这段内容：

> 「注意力的瓶颈不在算力，而在上下文窗口里能同时放下的有效信息量。」

请逐句解释这段内容在讲什么：把其中的术语、隐含前提和它想说明的结论都说清楚。
```

这样 AI 不需要猜「你说的是哪句」，也不需要你重新打字。

## 四、术语表

- **伴随式**（companion）：AI 不占据主视线，但在你需要时立刻在场。
- **选区**（selection）：浏览器 `window.getSelection()` 给出的那段 DOM 文本。
- **引用块**（quote）：把选区原文 + 出处拼成一条消息的前半段。
